# Git & GitHub Workflow – Week 1 Day 5

## 1. What is Git?

Git is a version control system used to track
changes in source code.

## 2. What is GitHub?

GitHub is a cloud platform used to store and
collaborate on Git repositories.

## 3. Branching

Branches allow developers to work on different
features without affecting the main branch.

## 4. Git Commands

- git status – Check repository status
- git branch – List branches
- git checkout -b – Create a new branch
- git add . – Stage changes
- git commit – Save changes
- git push – Upload changes to GitHub
- git merge – Combine branches
- git rebase -i – Edit and squash commits

## 5. Merge vs Rebase

Merge combines changes from different branches
and preserves branch history.

Rebase moves commits onto another base commit
to create a cleaner linear history.

## 6. Pull Request

A Pull Request is used to propose code changes
for review before merging into the main branch.

## 7. Merge Conflict

A merge conflict happens when Git cannot
automatically combine changes.

It can be resolved by reviewing the affected
files, selecting the correct content, staging
the resolved files and completing the merge.

## 8. .gitignore

The .gitignore file prevents unnecessary files
such as node_modules and environment files
from being tracked by Git.
